派生一个子代理，在独立的上下文里完成一个子任务，结束后只把它的最终报告（<task_result>）交回给你。

何时用：
- 需要大量搜索/阅读才能回答的问题（例如「找出所有调用 X 的地方并总结用法」），用 agent=explore，避免把一堆中间结果塞进你自己的上下文。
- 边界清楚、可以独立完成的多步子任务（例如「给模块 Y 补测试并跑通」），用 agent=general。

用法：
- 子代理看不到你和用户的对话：prompt 要写全目标、背景、相关文件路径、完成标准和希望的报告格式。
- explore 永远只读；general 默认继承当前权限模式，mode=read-only 可强制只读。子代理需要的审批会照常弹给用户。
- max_steps 控制子代理最多走多少步；model 可指定别的模型（默认同你）。
- 子代理的报告是给你看的，用户看不到：拿到结果后由你核对并向用户总结。

并行：
- 同一步里发出多个 task 调用，只读的子代理（explore、mode=read-only）会同时运行（有并发上限，超出的排队）。互相独立的调研就一次发多个，别一个一个等。
- 多个会改文件的子代理（general）同一步发出时，在 git 仓库里会各自进一个独立的 worktree 分支并行，改动不进主目录；报告末尾的 [worktree] 段落写了分支和改动文件，是否合并要先问用户。不是 git 仓库时按顺序执行。
- isolation：auto（默认，按上面的规则）/ worktree（只有一个也放进独立 worktree）/ none（在主目录里按顺序执行）。只读和计划模式下不能用 worktree。
- 并行的子代理之间看不到彼此的改动：别让两个子代理改同一批文件。

何时别用：
- 读一两个已知文件、跑一条命令这类简单操作（直接用对应工具更快）。
- 需要和用户来回确认的事。
- 子代理不能再派生子代理。
