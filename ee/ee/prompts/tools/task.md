派生子代理在独立上下文里完成子任务，只交回最终报告。explore 只读、general 可读写；普通子代理看不到对话，prompt 要写全目标、背景、路径和完成标准，fork=true 则继承你的完整上下文。

## 规则
- 大量搜索阅读或边界清楚的独立子任务才用 task（简单操作直接做），互相独立的调研在同一步并行发多个；子代理的报告只有你看得到，核对后再向用户总结。
- 同一步多个 general 在 git 仓库里各进独立 worktree，合并前先问用户；别让它们改同一批文件。
- **已经聊过一段、子任务要沿用这些上下文时，加 fork=true**：普通子代理用独立历史，它的每个请求都和你的对话对不上前缀，缓存命中不了、要按全价重算一遍；fork 继承你的上下文，第一个请求就能命中缓存。判断标准是「子任务需不需要我上面已经说过的内容」——需要就用 fork（prompt 里也不必重复背景），纯粹另起炉灶的调研才用普通模式。
