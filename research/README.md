## 规则

1. 想做事 → 只信 `roadmap-current.md`。
2. 想知道某个决定为什么这么定 → 才翻历史设计。
3. 两者冲突 → **以当前路线和实际代码为准**，并把冲突修进 `roadmap-current.md`，不要在历史文件里追加第三层声明。
4. 新完成的阶段要更新 `roadmap-current.md` 的状态表与执行记录，否则下一个人会把已完成的工作重做一遍（本项目已经发生过一次：D6-1 的 U1–U7 已提交，但入口还写着「D6 尚未开始」）。
